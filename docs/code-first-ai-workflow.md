# Code-First AI-Reviewed Workflow

Welcome to the **Code-First AI-Reviewed Workflow**. This document outlines the end-to-end pipeline designed to accelerate feature delivery by eliminating "pixel-perfect" design bottlenecks, automating code reviews, and enforcing architectural consistency.

---

## 1. Overview & Team Roles

This workflow relies on three core team members acting in concert with the AI Tech-Lead Stack. By shifting from a "Design-First" to a "Code-First" methodology, each role focuses on high-value tasks while the AI handles the boilerplate and visual validation.

### 👥 The Product Manager (PM)
**Goal:** Define business requirements and kick off the feature.
- **Action:** The PM provides raw requirements via the Tech-Lead Stack Agent Chat.
- **Value:** No need to wait for a designer to build Figma mockups. The PM initiates the creation of a functional, base-theme Shadcn/Radix skeleton instantly.

### 💻 The Developer (Dev)
**Goal:** Implement business logic and wire data.
- **Action:** The Dev receives an automated Discord ping that a new UI branch is ready. They pull the branch, run `pnpm install` (all Shadcn/Radix components were already added by the AI during skeleton generation), and connect the UI to real data/APIs.
- **Value:** The Dev doesn't have to build complex UI from scratch or guess spacing/colors. They inherit a fully accessible, brand-compliant skeleton and focus purely on logic.

### 🎨 The Designer
**Goal:** Final visual sign-off and brand alignment.
- **Action:** After the Dev opens a PR, the AI reviews the UI. Once the AI verifies the code meets the 90%+ alignment threshold, it pings the Designer in Discord with a link to Chromatic.
- **Value:** The Designer is freed from drawing every state in Figma. They only step in at the very end to do a rapid visual QA on the *actual* compiled component in the browser.

## 2. Step-by-Step Walkthrough

### Phase 1: Initiation (The PM)
1. **Request:** The PM opens the Tech-Lead Stack Agent Chat and asks to run the `ui-spec-generator` workflow with a set of requirements.
2. **AI Action:** The AI Tech-Lead securely executes `git checkout main`, pulls the latest code, and creates a new branch (e.g., `feature/ui-spec-dashboard`).
3. **Skeleton Generation:** The AI maps the requirements to standard Shadcn components, writes the raw React/Tailwind code using brand tokens, and commits the code.
4. **Handoff:** The AI runs `git push -u origin <branch>` and triggers the developer webhook.

### Phase 2: Implementation (The Dev)
1. **Notification:** The development team receives a Discord ping (via `discordDevWebhookUrl`) notifying them that the new branch is ready.
2. **Data Wiring:** A Developer checks out the branch, reads the `task.md` left by the AI, and wires up the real database queries, API calls, and state management.
3. **PR Creation:** Once the logic is complete, the Developer opens a Pull Request on GitHub and adds the designated UI label (e.g., `gilly-ui`).

### Phase 3: Review & Sign-off (The AI & The Designer)
1. **AI Review Triggered:** The GitHub Action automatically fires a request to the Tech-Lead Stack, creating a Design Review session.
2. **Iteration Loop:** The AI pulls the Chromatic build of the PR and compares it against base tokens (or an optional Figma link). It will mandate code changes to the Developer if the alignment score is below 90%.
3. **Designer Handoff:** Once the AI is satisfied (Score ≥ 90%), it updates the session status to `READY_FOR_DESIGNER_GATE` and fires a webhook (`discordWebhookUrl`) to the Designer's Discord channel.
4. **Final Approval:** The Designer clicks the Chromatic link in Discord, performs a 60-second visual review, and approves the PR.

## 3. Real-World Simulated Example

### The Scenario
**Product Manager (Sarah)** needs a new "User Management Table" with a search bar and a date filter.

### 🎬 Action 1: The PM Initiation
Sarah opens the Tech-Lead Stack dashboard, goes to the Agent Chat, and types:
> *"Run the ui-spec-generator workflow. I need a User Management page at `/admin/users`. It needs a data table showing Name, Email, Role, and a Date Range Picker to filter join dates."*

**The AI responds:**
> *"Acknowledged. I have analyzed the repository, created branch `feature/ui-spec-user-management`, and implemented the `DataTable`, `Input`, and `DateRangePicker` components using your brand tokens. I have pushed the branch to origin and notified the Dev team."*

### 🎬 Action 2: The Dev Handoff
In the `#dev-team` Discord channel, a new message appears instantly:
> **🚀 New UI Spec Branch Ready**
> A new feature branch has been generated by the AI Tech-Lead and is ready for development.
> **Project:** Gilly 
> **Branch:** `feature/ui-spec-user-management`

**Developer (Dan)** clicks the notification, pulls the branch, and sees a fully styled, static table. Dan spends 2 hours wiring up Prisma queries and React Query hooks to populate the table. Dan opens a PR and adds the `gilly-ui` label.

### 🎬 Action 3: The AI Review
When Dan opens the PR, the GitHub Action automatically pings the Tech-Lead Stack. 
The AI reviews the Chromatic build and notices Dan accidentally used `bg-blue-500` for a button hover state instead of the required `bg-primary/90`. 
The AI blocks the PR and comments: *"Please use brand tokens for hover states."*
Dan fixes it and pushes the update.

### 🎬 Action 4: The Designer Sign-off
The AI re-evaluates, scores the UI at 98%, and fires a webhook to the `#design-team` Discord channel:
> **🎨 Design Review Ready**
> The AI has verified the implementation for `feature/ui-spec-user-management`.
> **Alignment Score:** 98%
> **Chromatic URL:** [Click Here to Review]

**Designer (Diana)** clicks the link, sees the table looks perfect, and clicks "Approve" in Chromatic. The feature is merged. 

**Total time from idea to production:** 4 hours. **Total time spent in Figma:** 0 hours.
